- Routes SFF Change Image through the shared backend-neutral Creator as an explicit replacement plan.
- Preserves exact sprite identity, axis, palette assignment, physical order and source provenance during reviewed replacement.
- Adds atomic cleanup proposals for a temporary palette when its final explicitly owned placeholder sprite is removed.
- Keeps temporary palettes when any sprite, palette link, authored code reference or unresolved dynamic reference remains.
- Seals archive, lifecycle-registry and authored-reference evidence into the package and revalidates it before building and adoption.
- Shows both temporary-palette delete and keep reasons in the Creator's final review.
- Bounds-checks physical sprite and palette link indexes in the built-in SFF v2.1 PNG8 writer.
- Allows an exact physical target-SFF sprite to act as a sealed automatic-axis reference.

- Detects partial palette alpha that SprMake2 cannot preserve, retains the exact reviewed source for package-only/built-in workflows, and disables SprMake2 Build/Compare with a precise reason instead of flattening alpha or trusting its false-success exit code.
- Adds physical SprMake2-versus-built-in golden coverage for the normalized noncanonical PNG8 path.
- Adds deterministic header-only empty-archive output to the Compare-only built-in profile, its independent strict-validation golden, and the adoption-disabled runtime certification corpus.
- Versions the hardened independent gate as `sff-v2.1-png8-strict-v2`: aggregate decoded-pixel limits, complete reviewed entry/compression/crop/table-order checks, duplicate physical-palette rejection, bounded linked metadata, exact canonical byte coverage, unique PNG transparency chunks and valid PNG reserved type bits. Bundled SprMake2 uses a separate named compatibility profile that permits only zero-filled layout padding and bounded legacy unused offsets; built-in output remains on the stricter canonical profile.
- Makes Axis-before-Crop backend-neutral by sealing the exact cropped PNG and crop-origin axis delta, with physical SprMake2/built-in semantic parity coverage.
- Shows backend-specific capability limits in Creator before execution: legacy SprMake2 autocrop keeps SprMake2 Build and Package Only available while disabling only Compare Both, and the certified empty-archive profile no longer requires an unused palette.
- Adds explicit Index-order and Reversed Photoshop-order interpretation for temporary ACT/PNG palettes; the choice rechecks sprite compatibility, appears in final review, and is sealed into provenance and the immutable build specification before the SprMake2 adapter normalizes it.

- Preserves arbitrary per-row stored ACT assignments as explicit palette IDs in Creator review, the immutable specification and regenerated SprMake2 option blocks. List mode exposes the assignment on each source row.

A physical SprMake2 differential, independent built-in golden and palette-applied runtime fixture seal this case; pre-release adoption is permitted only through the dual-verified workflow above.
- Requires every used `[Pal]` row to declare a contained ACT, full `0,255` range and explicit `pal.reverseact`; changed bytes, missing tables, duplicate IDs, collisions and ambiguous table order fail closed. Unused palette rows remain ignored.
- Keeps SprMake2 available as an explicit fallback while the in-house writer remains gated from release-default status pending physical certification.

- Retains mixed per-sprite duplicate choices in the immutable backend-neutral specification while emitting no runnable SprMake2 DEF or CMD when its one global duplicate switch cannot represent the reviewed plan.
- Records the adapter unavailability in the specification, receipt, mapping and validation report, and rejects execution again at the host boundary.
- Completes the offline-safe PNG/BMP/PCX batch-preparation path: the author deliberately keeps picker order or chooses natural numeric filename order, chooses 1–12 digit padding, and reviews the resulting old-to-new map before execution. Originals remain untouched, collisions fail before conversion, every copied/converted PNG is structurally and CRC validated before the atomic destination write, source/output hashes and output format are retained in provenance, and temporary conversion files are removed. In-house converters preserve uncompressed indexed BMP, RLE8 BMP and indexed PCX pixels/palettes plus 24/32-bit BMP and three-plane PCX color; configurable ImageMagick is only a fallback for uncommon variants.
- Makes PNG-folder intake explicit and restart-safe: authors choose the selected folder only or contained subfolders, natural relative-path order is deterministic, linked entries are skipped, traversal/depth/file/entry limits fail the whole batch instead of truncating it, and validated immutable working copies retain original relative-path/hash provenance in the project cache.
- Removes silent source-limit slicing from loose-file, folder, prepared-image, sheet, GIF, and PSD Creator intake; an over-limit merge now leaves the retained draft unchanged and explains the limit.
- Retains missing or invalid reviewed PNG rows, stable source ownership and per-row overrides across draft recovery as visibly unavailable blockers instead of silently shrinking the approved batch.
- Hardens portable Creator-plan import: only explicit contained project-relative hints open automatically; absolute, escaping, linked, wrong-type, duplicate-identity and orphan-override records fail closed, while external paths remain visible but unread as unresolved rows.
- Makes portable target-owned operations fail closed rather than silently shrink: source/palette/target hashes are mandatory, orphan path hints and out-of-range palette IDs are rejected, and deletion/replacement rows must remain unique, in range, present in the reviewed target, unambiguous, non-protected, and exactly revalidatable.
- Makes Marked, Visible and saved SFF batch scopes fail as a whole if any reviewed physical sprite index is stale or missing; export and mutation tools can no longer continue with a silently reduced subset.
- Quarantines malformed retained Creator data instead of normalizing it into a smaller executable draft. Duplicate/missing source ownership, orphan overrides, malformed or repeated palette/deletion/replacement rows, and truncated filename/reservation tables remain visible integrity blockers across repeated recovery passes and portable-plan export/import. Even a fully quarantined zero-row draft remains listed in Recovery Center and keeps Discard available.
- Makes preserved legacy SprMake2 manifest deletion exact: every reviewed physical selection must still exist exactly once in both the active SFF and manifest. A stale index, missing row, repeated selection, repeated active identity, or repeated manifest row rejects the whole batch before any text write.
- Adds exact-source relinking for one marked unavailable row. Relink requires the original reviewed SHA-256, stores a restart-safe working copy, preserves identity/ownership and every per-row choice, and rejects changed artwork as a new review.
SFF Creator source review now includes a bounded List / Contact Sheet switch. Contact Sheet loads no more than 48 hash-checked, host-generated 96-pixel indexed thumbnails per page and shares the same search, filters, marks, ordering, and paging as List mode. Stored/FX assignments render through their effective ACT or target-SFF table in both the contact sheet and full axis/crop preview, so review matches the intended archive interpretation rather than the PNG's embedded colors. Changed, oversized, or unsupported sources remain labelled instead of loading unrestricted file URLs; exact group/index/axis/crop/palette editing stays in List mode.

Built-in SFF certification now includes a fixed-seed 32-archive deterministic property matrix. It strict-validates physical order, axes, palette order, varied RGBA/index payloads, backward sprite/palette links, repeated identities, boundary values, deterministic bytes, and fail-closed reserved-header corruption under one sealed aggregate corpus hash. Separate deterministic and physical SprMake2 goldens cover explicit stored-palette overrides. The runtime corpus now writes expected-render PNGs with each sprite's assigned table rather than assuming the source PNG PLTE is the display palette. This is offline regression evidence; author-only pre-release adoption additionally requires a fresh SprMake2 comparison and explicit confirmation, while release-default status still requires the real IKEMEN and platform gate.
