IKEMEN ZSS Tools 0.79.221

Saved SFF view organization without physical reordering

- The SFF viewer now defaults clearly to Original archive order and offers Saved view organization as an optional display mode.
- Custom view orders use an explicit drag handle with an eight-pixel movement threshold. Pointer cancellation and Escape abandon a drag, filters lock ordering, and Alt+Up/Down provides a keyboard route with position announcements.
- Applying a view order is a reviewed two-step action. The host issues a one-use token bound to the exact archive fingerprint, complete physical occurrence list, name, order, and saved-metadata generation.
- Saved orders distinguish duplicate group/index occurrences. Pixel, axis, palette-assignment, and link-target edits keep the same physical occurrence in its saved visual position while showing that it changed.
- If the physical inventory changes, unchanged rows are recovered only from unique exact evidence. Ambiguous duplicates remain visibly stale and new/unmatched rows remain visible; retirement of stale metadata is disclosed during review.
- View organizations are bounded, generation-checked viewer metadata. They do not write the SFF, image bytes, palettes, links, group/index identities, or physical sprite order.
- Storage rejects malformed or oversized retained state instead of silently truncating it. Failed acknowledgements and verification mismatches are reported as committed-but-unverified and require reload/verification.
- Physical SFF sprite reordering remains deferred as a later Advanced feature with separate writer, link, transaction, recovery, and compatibility certification.
