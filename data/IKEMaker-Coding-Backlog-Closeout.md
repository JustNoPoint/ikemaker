## Status rules

- **Source complete:** current implementation and focused automated evidence
  cover the recorded coding scope. Physical testing may remain separately.
- **Coding open:** a concrete, authorized implementation gap remains.
- **Physical pending:** installed UI, engine, platform, or desktop interaction
  must be checked manually; this is not unfinished source code.
- **Held/deferred:** an optional later product slice, publication, paid service,
  or explicitly shelved compatibility target. It is not silently implemented as
  part of this closeout.
- **Duplicate/superseded:** a later implementation or clarified contract already
  owns the behavior. Do not create a parallel editor, browser, writer, or draft.

exact retained operation without losing recovery evidence. Detach requires the
operation/revision identities, a unique request hash, a bounded reason, and the

backend, or changes project assets. Replay, stale identity, archive tampering,
and silent re-retention of the archived operation fail closed.

## Closeout procedure

For each admitted coding-open row: New Dev reviews the boundary; implementation
extends the existing owner; focused regressions and syntax checks pass; the
authoritative backlog is updated; New Dev performs a post-change gap review; and
the row moves to source complete. The goal is complete only when no coding-open
row remains. Physical-only items are handed off honestly rather than called
source defects.
